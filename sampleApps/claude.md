# コミュニケ-ション
- 日本語で応答する。(コード、変数名は英語)
- 要点を簡潔に応答する。
- 複雑なタスクはリサーチ→計画→実装→検証のフェーズを踏まえる

# 技術スタック
- 形態：Edgeブラウザ拡張機能
- フロントエンド：TypeScript + HTML/CSS
- バックエンド：なし（クライアント完結）
- データ管理：chrome.storage（または localStorage）

# コーディングルール
- 関数型のアプローチを優先する
- 厳密に型を定義する
- 仕様書の仕様Noと紐づけた簡潔なコメントを記載する

# 仕様書のあつかい
- 仕様書は`specs/`ディレクトリで管理
- 実装は必ず仕様書に従い、仕様にない実装はしない
- 仕様と実装が矛盾した際は、仕様書を正として実装を直すか、先に仕様書を直してからそれに矛盾しない実装をする

# ディレクトリ構造
```
src/
    components/ ←画面・UIコンポーネント
    lib/        ←ドメインロジック、バリデーション
__tests__/
    components/ ←コンポーネントのテスト
    lib/        ←ロジックのテスト
specs/
```
# ブラウザ確認
- coder環境を用いているため、プレビュー画面の動作確認は`npm run build`→`npm run preview`を利用してください。
- 拡張機能として確認する場合は`npm run build`後、Edgeの拡張機能ページで`dist/`を「展開して読み込み」してください。
- テストは`npm run test`、型チェックは`npm run typecheck`。
