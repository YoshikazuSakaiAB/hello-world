# 体験① Vibe Coding — チームの日報アプリ

> **対応スライド**: 10–13（Vibe Coding）
> **パラダイム**: Prompt Engineering — 「何を聞くか」で勝負
> **進行形式**: 講師デモ中心＋各自 5 分＋限界診断の座談（**25 分**）
> **v2 での変更**: 受講者は Vibe 既習者が多いため、フルハンズオン 30 分 → デモ＋座談 25 分に短縮

## 学習目標

- 一言の指示だけでアプリが動き出す **速さ** を体感する
- コードを読まずに結果だけで会話する **Vibe の UX** を知る
- 規模が大きくなると品質・再現性・引き継ぎやすさが崩れる **限界** を自分の目で確認する
- 体験② 以降で学ぶ「仕様 / ハーネス」の必要性を、言葉ではなく **実感** として持ち帰る

---

## お題

**「チームの日報アプリ」を Next.js で作る。**

> 体験②以降は Vite+React+Vitest に切り替えるため、このアプリはここで捨てます。Vibe の「ノリで作る」感を優先した意図的な選択です。

## 進行（当日 25 分）

### アジェンダ

| 時間 | セクション | 形式 | ねらい |
|---|---|---|---|
| 0–5 min | Vibe Coding とは？おさらい | 講義 | Karpathy の定義、強み・注意点を再確認 |
| 5–15 min | **ライブデモ**：日報アプリを Vibe で作る | 講師実演 | 最初の一言 → 追加指示 → 方向転換で破綻する様子まで見せる |
| 15–20 min | 各自 5 分だけ触る（任意） | 個人 | 手元で気軽に試す。全員動かなくて OK |
| 20–25 min | 限界診断の座談 | グループ共有 | 何に困ったか？ 体験②への伏線 |

### 講師デモのプロンプト例（3 段階）

講師はコードを **開かず**、結果画面だけ見せながら以下のプロンプトを段階的に打ちます。

```text
# 第 1 段階（0:00〜3:00）— 最初の一言
Next.js で日報アプリを作って。
名前と今日やったことを入力して、一覧表示できるようにして。

# 第 2 段階（3:00〜7:00）— 追加指示を重ねる
見た目をもっときれいにして。
日付で絞り込めるようにして。
カテゴリ分けを追加して。

# 第 3 段階（7:00〜10:00）— 方向転換
グラフで投稿数の推移を見せて。
ダークモード対応して。
```

第 3 段階で既存機能が壊れる / 破綻する瞬間が出てきます。**それを隠さず見せる** のがポイント。

### 各自 5 分（任意）

手元で同じプロンプトを試しても OK。時間が短いので、動かなくても問題ありません。

### 限界診断の座談（観点）

ホワイトボードや共有メモに以下を書き出します：

- 速さはどうだった？
- 品質は？コードは読める？
- 同じ指示で同じ結果になりそう？
- 2 週間後の自分がこのコードを引き継げる？

---

## 自習向け（30 分版）

当日参加せず自分で Vibe を触ってみたい人向け：

| 時間 | やること |
|---|---|
| 0–5 min | 最初の一言（上の第 1 段階）を投げて、動くものを作る |
| 5–15 min | 追加指示を重ねて機能を育てる（第 2 段階） |
| 15–25 min | 方向転換・大きな変更を試す（第 3 段階） |
| 25–30 min | 下の「振り返りメモ」を書く |

---

## 振り返りメモ

```text
### 速さ
- 動くものができるまでの時間:
- 追加機能の実装スピード:

### 品質
- コードは読めそう？:
- テストはある？:

### コントロール
- 意図通りに動いた？:
- 想定外の動きはあった？:

### チーム開発で使えそう？
- 他の人が引き継げそう？:
- 同じ指示で同じ結果になりそう？:
```

---

## 次へ（体験② への伏線）

振り返りメモで **困ったこと・不安だったこと** を具体的に書き出しておきましょう。
たとえば次のような観点は、体験② の `CLAUDE.md` や仕様書に直接反映できます。

- 「同じ指示を 2 回投げたら違う UI が出た」 → **CLAUDE.md にコーディング規約を書く**
- 「テストが無くて壊れてないか不安」 → **仕様書に受入条件を書く**
- 「他の人が触ったら壊しそう」 → **プロジェクトルールを Git で共有する**

→ 体験②（[`../exercise-2-sdd/`](../exercise-2-sdd/)）で、この不安を **仕様というガードレール** で制御します。
