# Create Branch — ブランチ作成・移動スキル

## 目的

このスキルは git ブランチ作成の「うっかりミス」を防ぐためにある。
典型的なミス:

- 未コミット変更を持ち込んだままブランチを作る
- main が古い状態からブランチを分岐させる
- チームの命名規則から外れたブランチ名をつける

---

## 手順（4 ステップ）

### Step 1 — 未コミット変更の確認

```bash
git status
```

**なぜ先に確認するか**: 未コミット変更がある状態でブランチを切ると、
変更が新ブランチに「乗ったまま」になる。意図しない場合が多く、
後から「あの変更どこいった？」という混乱を生む。

- `nothing to commit, working tree clean` → Step 2 へ進む
- 変更が検出された場合 → **ここで中断** し、以下をユーザーに提示する:

  ```
  未コミットの変更があります。以下のどちらかを選んでください：

  A) 変更を一時退避する（stash）
     git stash push -m "作業メモ"

  B) 変更をコミットする
     git add <files>
     git commit -m "wip: 作業中"
  ```

  ユーザーが対応を完了したら Step 2 へ。

---

### Step 2 — main から最新化

```bash
git fetch origin
git switch main
git pull origin main
```

**なぜこの順序か**: `fetch` でリモートの状態を取得してから
`pull` することで、最新の main を起点にブランチを分岐させる。
古い main から分岐すると後でコンフリクトが増える。

---

### Step 3 — ブランチ名の対話決定

ユーザーに以下を順番に確認する。

**① プレフィックス選択**（CONTRIBUTING.template.md 準拠）

```
何のためのブランチですか？番号で選んでください：

1) feat     — 新機能の追加
2) fix      — バグ修正
3) docs     — ドキュメントの変更のみ
4) refactor — 機能変化を伴わないコード改善
```

**② 用途の説明から slug を生成**

ユーザーの説明（例: "ログイン画面のバリデーション追加"）をもとに、
以下のルールで slug を生成してユーザーに確認する：

- 英小文字 + ハイフンのみ（例: `add-login-validation`）
- 単語数は 2〜4 語を目安
- 日本語が含まれる場合は英語に意訳する

**③ ブランチ名の確定**

```
作成するブランチ名: feat/add-login-validation

この名前でよいですか？（変更する場合は修正案を入力）
```

---

### Step 4 — ブランチ作成・移動

```bash
git switch -c <prefix>/<slug>
```

**なぜ `checkout -b` でなく `switch -c` か**: `git switch` は
ブランチ操作専用コマンドで意図が明確。`checkout` は多機能すぎて
教材として使うには混乱を招きやすい。

---

## 完了報告

ブランチ作成が成功したら、以下の形式で報告する：

```
ブランチを作成して移動しました。

  ブランチ名: feat/add-login-validation
  起点: main（最新）

次のステップ: 作業を進めたら git add → git commit でコミットしていきましょう。
```

---

## トラブルシューティング

| 状況 | 対処 |
|---|---|
| `main` が存在しない（`master` など） | `git branch -a` でデフォルトブランチ名を確認してユーザーに報告 |
| `git pull` でコンフリクト | コンフリクト解消をユーザーに依頼してから再実行 |
| 同名ブランチが既に存在する | slug を変更するよう提案する |
