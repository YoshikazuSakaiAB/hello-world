# 開発ガイドライン

> このファイルは開発者（人間）と AI エージェントの両方を読者とするコード規約ハブです。
> `CLAUDE.md` が AI 向けの制約であるのに対し、こちらは **理由と原則** を説明する位置づけです。

## 原則

1. **シンプルさを優先** — 3 回繰り返されて初めて抽象化する
2. **既存コードを優先して再利用** — 新規作成より既存関数・ユーティリティの活用
3. **境界で検証、内部では信頼** — ユーザー入力・外部 API の境界でのみバリデーション
4. **コメントは「なぜ」のみ** — 「何を」はコードが語る

## スタイルガイド

### 命名

- 変数・関数: `camelCase`
- 型・クラス: `PascalCase`
- 定数: `SCREAMING_SNAKE_CASE`
- ファイル: {{例: `kebab-case.ts` または `snake_case.py`}}

### エラーハンドリング

- {{例: Result 型 or try/except でドメイン例外を明示的に扱う}}
- ユーザーに見せるエラーメッセージは `i18n/` に集約
- ログには PII を出さない

### テスト

- テストはドキュメントとして読めるように書く
- モックは外部 I/O の境界のみ
- 1 テストケースで検証する振る舞いは 1 つ

## ツール設定への参照

- Linter: [`eslintrc.template.json`](./eslintrc.template.json)
- Formatter: {{例: Prettier / Black の設定ファイル}}
- Type Checker: {{例: `tsconfig.json` / `pyproject.toml`}}

## AI エージェントとの協働

- AI が生成したコードは必ずレビュー
- AI は仕様書 (`specs/`) と ADR (`docs/adr/`) を参照してから実装する
- AI が既存コードを書き換える場合、変更理由を PR 本文に残す
