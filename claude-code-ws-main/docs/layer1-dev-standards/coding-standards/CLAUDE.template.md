## やってはいけないこと

- テストファイルを書き換えて通すこと（実装を直す）
- `git commit --no-verify` でフックをスキップすること
- 仕様書にない機能を勝手に実装すること（YAGNI）
- 公開 API の破壊的変更を PR 記載なしで行うこと

## このファイルの扱い方（懐疑的メモリの原則）

- ここに書かれた情報は **古い可能性がある**。実装前に現在のコード・仕様と照合すること。
- 矛盾があれば **コード・仕様を正** とし、このファイルの該当箇所を更新して PR に含めること。

## スコープの使い分け

- `~/.claude/CLAUDE.md` — 全プロジェクト共通の個人設定（広い）
- `./CLAUDE.md` — プロジェクト共有（本ファイル / Git 管理）
- `./<module>/CLAUDE.md` — モジュール固有（狭い ＝ 優先）
