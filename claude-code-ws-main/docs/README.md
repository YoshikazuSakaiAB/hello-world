# AI駆動開発 3層スタンダード・フレームワーク

`AI駆動開発標準の考え方.pptx` に基づく、仕様駆動開発のための **3 層スタンダード** の雛形集です。
ワークショップ参加者・組織が「AI 駆動開発のために事前に整備すべき標準」を手元にコピーしてすぐ使える状態にすることを目的としています。

## ドキュメントの役割の変化

| 観点 | 従来の開発 | AI駆動開発 |
|---|---|---|
| 文書の役割 | 工程の「成果物」 | AI への「入力ソース」または「出力スキーマ」 |
| 目的 | 品質保証・監査証跡・合意形成 | AI インプット品質の担保と生成物の構造・品質定義 |
| 誰が作るか | 担当者が作成し責任者が承認 | AI が自動生成し、担当者はレビュー・承認に集中 |
| 作り方 | 人が作成（テンプレ化で効率化） | コンテキストから AI が生成 → 人が承認 |
| 整合性確認 | 人の目 | AI が依存関係を追跡し矛盾を自動検出 |

> テンプレートは「人が埋めるフォーマット」から「**AI の出力スキーマ（構造・必須項目・品質基準の型定義）**」へ。

## 3 層の位置づけ

| Layer | 役割 | 配置先 |
|---|---|---|
| [Layer 1 — 組織の開発規約](./layer1-dev-standards/README.md) | 一度整備すれば全プロジェクトで再利用できる標準基盤 | 標準テンプレートリポ / プロダクトリポ |
| [Layer 2 — AI 出力スキーマ定義](./layer2-output-schemas/README.md) | AI が生成する各文書の構造・必須項目・品質基準の型定義 | Spec-Kit / AIDLC 設定 |
| [Layer 3 — コンテキストリポ構造ルール](./layer3-context-repo/README.md) | AI の生成品質はインプット質に直結 — 最も重要なレイヤー | Context Repository |

## ワークフロー

```
[1] コンテキストリポジトリ         ← Layer 3 の構造ルール
    (インタビュー / ペルソナ / 調査)
           ↓
[2] 仕様駆動開発ツール              ← Layer 2 の出力スキーマ
    (Constitution / Specify / Plan / Tasks)
           ↓
[3] 自動生成ドキュメント
    (StRS / SRS / 受入テスト / アーキ図 / DBスキーマ)
           ↓
[4] 人間のレビュー・承認
    (品質チェック / ビジネス判断 / 仕様確定)
           ↓
[5] プロダクトリポジトリ            ← Layer 1 の開発規約
    (実装 / テスト / CI/CD / リリース)
```

## 導入ロードマップ

| Phase | 内容 |
|---|---|
| **Phase 1 — 基盤整備** | Layer 1 の開発規約を整備・標準化。コード規約 / CI/CD / CONTRIBUTING を作成。ADR 運用を開始 |
| **Phase 2 — コンテキスト構造化** | Layer 3 の構造ルール策定。既存のインタビュー記録・ペルソナを統一フォーマットに移行 |
| **Phase 3 — AI出力スキーマ定義** | Layer 2 の各文書スキーマを定義。Spec-Kit / AIDLC に組み込み、パイロットで検証 |
| **Phase 4 — 継続的改善** | コンテキスト → 文書の自動生成パイプライン完成。文書間整合性チェック自動化、メトリクスに基づくスキーマ改善 |

**成功指標**: 文書作成時間 80% 削減 / 文書間不整合 95% 削減 / 新メンバーオンボーディング時間 60% 短縮

## 使い方

1. 組織としてまず `layer1-dev-standards/` の雛形を整備し、標準テンプレートリポを作成
2. 既存のプロジェクト知識を `layer3-context-repo/` の構造で整理
3. 実プロジェクトで `layer2-output-schemas/` を Spec-Kit / AIDLC 設定に組み込み、AI 生成を型で制約
