> **対応資料**: `claude-code-ws.pptx`（全60枚）

> **最終更新**: 2026-04-24

---

## 1. 再設計の背景

受講者アンケートから以下の傾向が見えた：

- **Vibe Coding はある程度経験済み**
  → ゼロから触らせる意義は薄い。講師ライブと「限界診断の座談」に振る
- **Harness Engineering への興味が最も大きい**
  → Hooks / Agents / Skills / Plugin / 体験④ に教育時間を寄せる
- **体系的に学べる教材がない**
  → 原理編・アーキ深掘り・3層スタンダードで「網羅性」を担保し、ハンズオンで「腹落ち」を作る

これを受け、旧 v1（1日集中 10:00–17:00・3体験均等配分）を **2日構成** に組み替え、Day2 をハーネス本編に寄せた。

| アンケート声 | v2 での対応 |
|---|---|
| Vibe は経験済み | 体験① を 35min → **25min**、デモ＋限界診断へ圧縮 |
| ハーネスに興味 | Hooks +15 / 体験③ +10 / 体験④ Appendix→**本編必修 55min** |
| 体系的に学びたい | 原理編フル / Skills・Agents・MCP フル / アーキ深掘り / **3層スタンダード 20min 新設** |

## 2. 全体像マップ

```
Day1（午後）: 原理 + Context Engineering
  └─ 「AI をガイドする側に回る」までの地図を作る

   [自宅課題 30〜40分: 日報アプリ題材で 5 工程の AI ハーネス構成を設計 → Day2 冒頭で発表]

Day2（午後）: Harness Engineering 本編 + スケール
  └─ 「AI に走らせる環境」を自分で組み、組織展開の輪郭まで見る
```

- Day1 は **原理 → 体験① Vibe（短縮）→ 理論（SDD / CLAUDE.md / Skills / Agents / MCP）→ 体験② SDD** まで。Context Engineering の全体像をインストールする。
- Day2 は **Hooks → 体験③ Agentic → 体験④ TDD Guard 再実装 → アーキ深掘り → 3層スタンダード → まとめ** の流れ。ハンズオン時間を合計 **125分（体験③ 70 + 体験④ 55）** 確保する。

### Day1→Day2 自宅課題（目安 30〜40 分・提出不要）

**体験② で作った日報アプリを題材に、5 工程（要件定義 → 仕様書作成 → 設計 → 開発 → 確認）の AI ハーネス構成** を Markdown 1 枚で構想する 1 課題（v3 で 3 課題 → TDD ハーネス → 実務全体 → 5 工程固定 → 30〜40 分・日報アプリ固定、と段階的に焦点化）。

- **お題**: 5 工程それぞれに Skill / Sub-agent / MCP / CLAUDE.md / 既存ツール（人手含む）を割り当てる。Hook は Day2 で扱うため任意（知っている人は挑戦可）。**完成例（Mermaid）を提示し、受講生はそれを参考に自分なりのワークフローを組む**（図の形式は自由）
- **TDD 制約**: **③ 設計の開発ルール** に **テスト先行 + 仕様適合チェック** を規約化（Day2 体験③④の前提と接続）
- **成果物**: 工程 × 要素マトリクス + ワークフロー図（形式自由）+ 採用理由（提出は不要、当日 Markdown / 画像を画面共有・印刷で見せられる状態に）
- **Day2 との接続**: 冒頭で **3–4 人ずつ 5 分発表** → **講師が 1 案をその場で選定** → その構成案を体験③（70 min）で全員でハーネス化（**② 仕様書作成〜⑤ 確認** が対象、① 要件定義はスコープ外）
- **狙い**: 受講生の構想がそのまま当日の実装題材になる構造にし、設計→実装の往復を強制的に発生させる
- 詳細: [`docs/materials/homework.md`](./materials/homework.md)
