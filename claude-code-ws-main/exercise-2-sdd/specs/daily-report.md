# 日報アプリ 仕様書

> 体験② のハンズオン用 **配布済み仕様書**。参加者はこの仕様書を読み、`CLAUDE.md` のルールと合わせて Claude Code に実装させます。
> 対応スライド: 15（SDD とは）／ 24（体験②の流れ）

## 概要

チームメンバーが日々の作業を記録・振り返りするための **日報アプリ**。バックエンドを持たず、ブラウザの localStorage に永続化する。

## ユーザーストーリー

- ユーザーとして、日報を投稿したい。なぜなら日々の作業を記録したいから。
- ユーザーとして、過去の日報を一覧で見たい。なぜなら振り返りをしたいから。
- ユーザーとして、日付やカテゴリで絞り込みたい。なぜなら特定の日の作業を確認したいから。

## 画面一覧

### 1. 日報投稿画面

| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| 名前 | テキスト | ✅ | 1–50 文字 |
| カテゴリ | セレクト | ✅ | 開発 / レビュー / ミーティング / その他 |
| 内容 | テキストエリア | ✅ | 1–1000 文字 |
| 日付 | 日付 | ✅ | 未来日は不可 |

### 2. 日報一覧画面

- 表示項目: 名前、カテゴリ、内容（先頭 100 文字）、日付
- デフォルトソート: 日付の降順
- フィルタ: 日付範囲、カテゴリ、名前

## 受入条件

> テストで検証可能な条件として記述（= Vitest のテストケースになる）。
> ハンズオン 25 分では **全件を実装する必要はない**。3 件回せれば SDD のサイクルを体感できる。

- [ ] 名前が空の場合、投稿ボタンが無効化される
- [ ] 投稿成功後、一覧画面に新しい日報が表示される
- [ ] 日付フィルタで絞り込んだ結果が正しく表示される
- [ ] カテゴリフィルタで「開発」を選ぶと開発カテゴリの日報のみ表示される
- [ ] 未来日を選択した場合、エラーメッセージが表示される
- [ ] ブラウザを再読み込みしても、投稿済みの日報が残っている（localStorage 永続化）

## 非機能要件

- レスポンシブ対応（モバイル幅 375px〜）
- **ダークモード対応は体験③ で追加する**（この段階では不要）
- データ永続化: **localStorage**（DB は使わない）

## 技術制約

- `CLAUDE.md` に記載のルールに従うこと
- データ永続化は localStorage に限定（バックエンドサーバーを立てない）
- テストは `__tests__/` に配置し、`npm test -- --run`（Vitest）で全て通ること
