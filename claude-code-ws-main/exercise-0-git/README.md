# [OPTIONAL] 体験⓪ Git 基礎 — Claude Code を使う前に最低限の Git を握る

> **対応スライド**: なし（前提知識補講）
> **位置づけ**: 当日メニュー外 — Git 未経験者向けの自習用オプション演習
> **パラダイム**: Claude Code 以前 — 「変更を記録し、共有し、戻れる」感覚を持つ

## 学習目標

- **リポジトリ／コミット／ブランチ** の 3 概念を自分の手で動かして理解する
- **ローカル → リモート → PR** の流れを 1 周する
- 同じ操作を **Claude Code に委ねた** とき、AI が何をどの順で実行するかを観察する

## お題

ローカルにメモ用の小さなリポジトリを作り、**ファイル編集 → コミット → ブランチ作成 → マージ → GitHub にプッシュ → PR 作成** までを 1 周します。

題材は本ワークショップ本筋の「日報アプリ」とは独立した **メモ 1 ファイル** のミニリポジトリです。Git 操作だけに集中するため、コードを書く要素は意図的に最小化しています。

---

## 事前準備

- GitHub アカウントを持っていること
- ローカルから GitHub にプッシュできる認証（HTTPS の Personal Access Token か SSH 鍵）が通っていること
- `git` と（後半で使う）`gh`（GitHub CLI）がインストール済み — 未インストールでも前半は動きます

> 認証で詰まる場合は当日講師に声をかけてください。**Git 操作の本筋ではない部分** で時間を取られないように。

---

## 進め方（45–60 分）

前半 25 分は **手で CLI を打って** 原理を掴み、後半 20 分は **Claude Code に委ねて** 差分を観察します。

### 前半: 手で打つ（25 分）

このリポジトリの **外** に作業ディレクトリを作って進めてください（このリポジトリ内で `git init` するとネスト管理になり混乱します）。

```bash
cd ~          # ホームに移動（場所は任意）
mkdir git-tutorial && cd git-tutorial
```

| 時間 | Step | 主なコマンド | 観察ポイント |
|---|---|---|---|
| 0–5 | リポジトリ作成 | `git init` / `echo "# memo" > memo.md` / `git status` | `.git/` ディレクトリができる。`status` は何を「未追跡」と言っている？ |
| 5–10 | 最初のコミット | `git add memo.md` / `git commit -m "first commit"` | `add` と `commit` で何がどこに移動した？ |
| 10–15 | 2 回目のコミット | `memo.md` を編集 → `git diff` → `git add` → `git commit` → `git log --oneline` | ログが伸びる。`diff` は何と何を比べている？ |
| 15–20 | ブランチ操作 | `git switch -c feature` → 編集して commit → `git switch main` → `git merge feature` | `main` は触っていないのに別人格が育つ感覚 |
| 20–25 | リモート連携 | GitHub で空リポジトリ作成 → `git remote add origin <URL>` → `git push -u origin main` | ローカル ↔ リモートの対応、`-u` の意味 |

> **詰まったら**: `git status` を打つ習慣をつけてください。Git は今の状態をかなり丁寧に教えてくれます。

### 後半: Claude Code に委ねる（20 分）

同じ作業ディレクトリで Claude Code を起動し、以下のプロンプトを順に投げます。**何が起きているか** を観察するのが目的なので、結果が出たらコマンド履歴と Claude の説明をスクロールバックして見直してください。

| 時間 | プロンプト例 | 観察ポイント |
|---|---|---|
| 25–35 | 「`memo.md` に今日の日付を追記してコミットして」 | Claude が打つコマンドの順序、コミットメッセージの作り方、`git status` を確認しているか |
| 35–45 | 「`fix-typo` ブランチを切って `memo.md` の typo を直して PR を作って」 | `gh` CLI を使うか、`git push` の前に何を確認するか、PR タイトル・本文をどう生成したか |

> **観察のコツ**: Claude Code は破壊的操作（`reset --hard`、force push 等）の前にユーザー確認を挟む設計になっています。「コミットを消して」と頼んでみると、安全側に倒した挙動が観察できます。
